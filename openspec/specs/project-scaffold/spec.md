## Requirements

### Requirement: Monorepo workspace layout
The repository SHALL be a pnpm workspace with `backend/` and `frontend/` as member packages, plus root-level shared tooling files (`pnpm-workspace.yaml`, root `package.json`, `.gitignore`, `README.md`).

#### Scenario: Fresh clone installs both apps
- **WHEN** a developer runs `pnpm install` from the repo root on a clean clone
- **THEN** dependencies for both `backend/` and `frontend/` are installed without needing to `cd` into either folder

### Requirement: Backend skeleton boots and documents itself
The backend SHALL be a NestJS 11 application, on Node.js 24.x and TypeScript 6.0.x, that starts successfully with no domain modules, connects to PostgreSQL 18.x via Prisma 7.x, and serves a generated OpenAPI document.

#### Scenario: Backend starts against local Postgres
- **WHEN** `docker compose up` has started the Postgres 18.x service and `pnpm --filter backend start:dev` is run
- **THEN** the NestJS application boots without errors and Prisma successfully connects to the database

#### Scenario: OpenAPI document is served
- **WHEN** the backend is running
- **THEN** an OpenAPI JSON document is available at a documented endpoint (e.g. `/api-json`), generated by `@nestjs/swagger`, reflecting whatever routes currently exist (even if only a health check)

### Requirement: Frontend skeleton builds and consumes the backend's API contract
The frontend SHALL be a React 19 + Vite 7 SPA, in TypeScript 6.0.x, with TanStack Router, TanStack Query, and Mantine 8 configured, and a script that regenerates its typed API client from the backend's OpenAPI document.

#### Scenario: Frontend production build succeeds
- **WHEN** `pnpm --filter frontend build` is run
- **THEN** Vite produces a static build with no errors, and no Node runtime is required to serve the output

#### Scenario: API client regenerates from backend OpenAPI document
- **WHEN** the backend is running and its OpenAPI document is reachable
- **THEN** running the frontend's codegen script (`openapi-typescript`) regenerates the typed API client in `frontend/src/api/` without manual edits

### Requirement: Local development database via Docker Compose
A root-level `docker-compose.yml` SHALL provision a PostgreSQL 18.x service for local backend development, matching the version used in CI.

#### Scenario: Local Postgres service starts
- **WHEN** a developer runs `docker compose up -d` from the repo root
- **THEN** a PostgreSQL 18.x container starts and is reachable at the connection string the backend's `.env.example` documents

### Requirement: Per-app CI pipelines
GitHub Actions SHALL run a backend workflow and a frontend workflow, each path-scoped to its own folder, each running install, lint, typecheck, and test (and build, for the frontend) on push/PR.

#### Scenario: Backend-only change triggers only backend CI
- **WHEN** a pull request changes only files under `backend/`
- **THEN** `.github/workflows/backend-ci.yml` runs and `.github/workflows/frontend-ci.yml` does not

#### Scenario: Frontend-only change triggers only frontend CI
- **WHEN** a pull request changes only files under `frontend/`
- **THEN** `.github/workflows/frontend-ci.yml` runs and `.github/workflows/backend-ci.yml` does not

#### Scenario: CI fails on lint or type errors
- **WHEN** either workflow runs against code with a lint violation or a type error
- **THEN** the workflow fails before reaching the test step
